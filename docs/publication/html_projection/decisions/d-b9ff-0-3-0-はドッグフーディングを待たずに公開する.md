## Context

0.3.0 の準備が終わった時点で、進行担当は公開の保留を進言した。理由は、ドッグフーディングのフィードバックで HTML の出力が変わりうること。利用者は保留すると文書の訂正が届かず作業しづらいと指摘した。

## Decision

公開する。

## Consequences

保留の理由は HTML 機能にのみ効き、出力が変わっても 0.3.1 で届ければ済む。天秤に載せていなかったのは保留を続ける費用だった。文書の訂正は公開するまで誰にも届かず、その間 GitHub の README は状態順序について誤解を招く記述のまま残り、cargo install で入る同梱スキルも旧版のままになる。

この判断から AGENTS.md の「公開を判断する」節を書いた。取り消せる操作と取り消せない操作を分け、判断待ちにするのは crates.io の公開と公開コミットの push とタグの push の3つだけとする。保留条件を3つ挙げ、保留は遅延ではなく順序であることと、理由を聞いたうえで公開を指示されたらその判断に従うことを明記した。
