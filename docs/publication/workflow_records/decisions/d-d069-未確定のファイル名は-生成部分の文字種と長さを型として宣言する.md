decision_scope: workflow の範囲照合に適用する。設計側は files を literal と generated の2種で宣言し、generated は固定の directory・prefix・suffix と、生成部分の文字種・長さを持つ。glob は採らない。理由は2つある。第一に、**  のように何も宣言していないに等しい宣言を書ける形を gy は受け入れない。decision に適用条件を、question に選択肢2つを必須にしているのと同じ理由で、宣言は書いた内容が意味を持つ形に制限する。第二に、glob のエスケープ・文字クラス・依存ライブラリの解釈の契約を gy が負わない。既存の same-set / subset / equal は変えず、新しい比較を明示的に選んだときだけ適用する。文字種の初期候補は ascii-digits と lowercase-hex とし、必要な実例が出た時点で追加を判断する。この追加は CheckKind に variant を足すため公開APIの非互換変更になるので、同じ版で DependencyRole・RuleConfig・FieldType・CheckKind に non_exhaustive を付け、版を上げる回数を減らす
