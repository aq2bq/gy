# q-321b (Q-23) 内容が同じと検算できる訂正のとき、設計の版を上げても承認を引き継げるようにするか

state: closed

scope: workflow_records
created: 2026-09-13
  closes d-d224 (D-31) 設計の版を上げた訂正で承認を引き継がない
## 出所

kokopelli-recurring-v2 の進行管理担当から 2026-09-13 に報告。N-11 を直すには design_proposal の版を上げる必要があり、版を上げると approval.target_revision との一致が崩れて人間の承認を取り直すことになる。変えたのはファイル名の書き写しだけで、設計の中身は変わっていない。承認の元になった設計提案は GitHub のコメントとして固定されており、同一性は誰でも検算できる。

報告者はマスターに3ターン使わせ、最終的に「検算できて取り返しがつくなら訊かない」と判断して裁可なしで進めた。

## 再現

挟み撃ちであることを確認した。

```
版を上げない → error: design_proposal.revision=r1 was already recorded with different contents; use a new version
版を上げる   → error: Equal check failed: approval.target_revision versus design_proposal.revision
```

## 論点

gy は中身の同一性を判定できない。判定できるのは記録された値の一致だけである。「訂正だから承認を引き継ぐ」を受け入れることは、gy が検査できない宣言に検査の成否を委ねることを意味する。

## 推奨

「引き継がない」を推奨する。

1. この事例の発生源は N-11 であり、それを解けばこの形では起きない。
2. 承認の版と設計の版の不一致は、今回の進行で gy が実際に止めた2件のうちの1件である。同じ検査を宣言で回避可能にすると、終盤に最も効く検査が最初に緩む。
3. 引き継ぎを認めても、承認を記録する主体は変わらない。gy は承認者を認証しないので、記録の正しさは運用側の規律に残ったままである。

引き継ぐ場合に得るものは、検算可能な訂正で人間を呼ばずに済むこと。代償は、訂正であるという宣言を偽れば承認が素通りすること。

N-11 を解いたあとも別の形（誤字の訂正など）で再発するかどうかは未確認である。再発した頻度を見てから決める余地がある。

## 2026-09-13 追記: 発生源が閉じた
