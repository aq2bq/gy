# gy の台帳

gy の書き込みは、そのノードにまだ無いもの（`missing`）と次に打てるコマンド（`next`）を出力に返す。手順を暗記するのではなく、出力に従う。

## セッションを再開する

1. `gy handover` で進行中の要求と件数を読む。警告は件数だけで、誰も待っていない論点と、担うニーズが全部閉じて未達の受け入れ条件もここに出る。ノードは `list` で探し、`show` の `missing` で隙間を読む。
2. `gy next` で前提の片付いたニーズを見る。
3. マスターへ差し出す 1 つを選び、`gy show <ID>` で読む。

## 1 つのニーズを進める

- ニーズは受け入れ条件を `targets` で指す。`need add` は出力の先頭に `id: <ID>` を出し、`next` が次のコマンドを示す。
- 本文は `need add` の `--body-file` で作成と一緒に入る（あとから `edit --body-file` でもよい）。`filed-as` の要求は `req add` で立て、使える決定と受け入れ条件を添える。
- 着手の前提は `depends-on` と `waits-on` の辺で表す。`next` はこれを見る。
- 決定が要るときは `decide`、論点が生まれたら `question add`。

## 終える

- ニーズは、`filed-as` の要求が完了すれば導出で `done` になる。要求を経由しないときは `need close`。閉じても受け入れ条件は満たされない。閉じたときの `missing` に未達の条件が出るので、証拠があれば `criterion satisfy`、取り下げるなら `link --remove <need> targets <ac>`。
- 日付は自分の場所の時刻で出る。他のエージェントに時点を伝えるときは日付でなく `seq` か ID を使う。
- 出力の `missing` が空になるまで埋め、`next` の形どおりに次を打つ。
- 台帳に書いたことと外の事実（実装・Issue・PR）は別である。外は人が確かめる。
